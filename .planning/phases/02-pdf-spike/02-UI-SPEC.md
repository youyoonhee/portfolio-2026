## Spacing Scale

Declared values (all multiples of 4). Exposed as `--space-*` custom properties in `@layer tokens`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge inner vertical padding, dt-to-dd gap |
| sm | 8px | Meta row gaps, chip gaps, list item gaps |
| md | 16px | Card inner padding (mobile), grid gap (mobile), paragraph spacing |
| lg | 24px | Card inner padding (tablet and up), grid gap (tablet and up), wrap side padding at 768px |
| xl | 32px | Gap between title block and content inside a section |
| 2xl | 48px | Gap between sub-blocks, section padding-block on mobile and tablet |
| 3xl | 64px | Section padding-block on desktop (>= 1024px), keyword block padding |

Spacing exceptions: none. Page wrap side padding is `clamp(16px, 5vw, 32px)` (16px floor, 32px ceiling, both scale tokens).

Layout and hit-target dimensions (NOT spacing tokens; they size components, not gaps): 44px minimum hit area (header links, hamburger, card links), 48px rows (keyword-list rows, open mobile menu rows), 64px mobile header and 72px desktop header height, 80px `scroll-margin-top` / `scroll-padding-top`, 88px meta `dt` column, 200px app-frame max width, 600/920px container breakpoints. These may be off the 4-point spacing scale where a platform target or component size demands it.
- Badge radius, card radius and shadow offsets are not spacing and are listed under Shape.

### Layout and breakpoints [DISCRETION]

| Name | Width | Behavior |
|------|-------|----------|
| mobile | < 640px | 1 column everywhere, hamburger menu, 375px is the design baseline |
| tablet | 640px to 1023px | project grid 2 columns, hamburger still used below 900px |
| desktop | >= 1024px | project grid 3 columns, inline nav, keyword section two-column |

- Page content max width: `--wrap-max: 1200px`, centered, side padding as above. Left and right content edges must be equal (design-taste house rule 4).
- Breakpoints are expressed with `@media (min-width: 640px | 900px | 1024px)` for page chrome (header, keyword section) and `@container` for the project grid so cards decide their own column count: `.company { container-type: inline-size; container-name: company; }`, grid columns from `@container company (min-width: 600px)` = 2 cols and `(min-width: 920px)` = 3 cols. This means the card grid responds to its section width, not the viewport.
- Hamburger replaces the inline nav below 900px (`@media (max-width: 899.98px)`); at 900px and up the nav is inline.
- No horizontal scrolling at 375, 768, 1440 (DSGN-02). Required guards: `html { overflow-wrap: anywhere }` is NOT used on body text. Instead: `body { word-break: keep-all; overflow-wrap: break-word; }` for Korean; `a[href^="mailto:"], .links a { overflow-wrap: anywhere; }` for long URLs and the email; `img, figure { max-inline-size: 100%; }`; grid children `min-inline-size: 0`.

## Typography

Single family Pretendard. Exactly 4 sizes and 2 weights are used in components. Heading and Display are fluid via `clamp()`; Body and Label are fixed px.

| Role | Size | Weight | Line Height | Notes |
|------|------|--------|-------------|-------|
| Body | 16px | 400 | 1.6 (body copy), 1.5 (UI text) | Descriptions, meta dd, nav links, buttons. Minimum text size on the page is 14px |
| Label | 14px | 600 | 1.4 | eyebrow, meta dt, badges, period, career period, footer small, skill dt. Letter-spacing `0.04em` only on English uppercase eyebrow |
| Heading | `clamp(24px, 2.4vw + 16px, 36px)` | 600 | 1.25 | h2 section titles only |
| Display | `clamp(48px, 6vw + 8px, 96px)` | 600 | 1.05 | h1 cover line and the big keyword in the keyword section (one shared token, no separate keyword size) |

Final size roles: exactly 4 (Body 16, Label 14, Heading fluid 24-36, Display fluid 48-96). The h3 project title uses Body 16px at weight 600 so weight, not size, carries the card hierarchy. Final weights: exactly 2 (400 and 600). Weight 700 is dropped [DISCRETION]: the 600 weight already gives enough contrast against 400 at every size, and skipping 700 removes 92 `unicode-range` subset files from the font payload. The `@font-face` declarations and `fonts/` therefore contain only 400 and 600 (CONTEXT allowed 400/600/700 as a ceiling, not a requirement).

Rules:
- `html { font-size: 100% }`; all sizes in rem equivalents (`1rem = 16px`).
- `h1, h2, h3 { text-wrap: balance; letter-spacing: -0.02em }`. Body: `text-wrap: pretty`. Korean body copy uses `word-break: keep-all`.
- English display text (`lang="en"`) uses `letter-spacing: -0.03em` at Display size only.
- Maximum measure for paragraphs: `max-inline-size: 60ch` (Korean: `36em`).
- Numbers in `.career-period`, `.period`, and contribution use `font-variant-numeric: tabular-nums`.
- Pretendard is declared as `font-family: "Pretendard", system-ui, -apple-system, "Apple SD Gothic Neo", "Malgun Gothic", sans-serif; font-display: swap;`.

### 1. Site header (fixed) [CONTEXT D-15, D-16]
