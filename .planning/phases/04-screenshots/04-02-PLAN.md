## Phase Goal

**As a** 포트폴리오를 검토하는 채용 담당자, **I want to** 프로젝트마다 실제 작업 화면을 비율에 맞는 프레임으로 보고 크게 확대해 보기를, **so that** 어떤 회사에서 어떤 화면을 직접 퍼블리싱했는지 바로 파악할 수 있고, 공개된 이미지에는 민감 정보가 없다.

<objective>
두 번째 조각: 사용자가 이미지를 승인해 넣었을 때 "공개돼도 안전하고 마크업이 맞다"는 것을 사람이 아니라 검사가 매번 증명한다. check-content가 이미지 figure를 정상 구조로 인정하고(빈 figure도 계속 인정), 새 check-images가 공개 이미지의 메타데이터·승인·참조 무결성을 감사하며, 둘 다 `npm run check`와 pre-commit에 들어간다.

Purpose: SHOT-02(EXIF 제거와 승인 게이트를 커밋 시점에서 강제), SHOT-03(width/height/srcset/alt 검증), D-03, D-10, D-12, D-13.

</objective>

## Trust Boundaries

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-08 | Information disclosure | EXIF/ICC/XMP surviving in a committed image | mitigate | check-images parses JPEG segments and WebP chunks (zero dependency, in pre-commit via `--fast`) plus sharp metadata in full mode; self-test proves positives are caught |
| T-04-09 | Information disclosure | Image committed without user approval | mitigate | check-images fails any folder without `status: approved`; runs in `npm run check` and pre-commit |
| T-04-10 | Information disclosure | Phone-like text in manifest | mitigate | `hasPhone` on every manifest string; failure output prints only the rule and path |
| T-04-11 | Tampering | Line-ending conversion corrupting images | mitigate | `.gitattributes` `img/** binary` |
| T-04-12 | Repudiation / bypass | Skipping hooks | mitigate | No `--no-verify` in any script or instruction; hook remains `core.hooksPath .githooks` |
</threat_model>
