# Quick 261122-s7k: submission PDF that looks like the desktop web page, as 16:9 slides

## User request (2026-11-22, in Korean, with decisions)
The user asked: "Can't you make it the same as the web screen?" and chose the following.

- **Method:** "the web screen as it is, with text kept". The PDF uses the **desktop web design (1440px wide)**, not the current A4 print layout.
  - **Same as the web:** cover circles on the ivory band, the sage half-circle dial, cards and colours.
  - **Text stays vector:** selectable and searchable, with clickable links. **No screenshots or bitmaps of text** (no html2canvas-style output; CLAUDE.md forbids it).
- **Keywords:** the 4 dial steps, one per page.
- **Page format:** landscape 16:9 slides, one section (or part of one) per page.

## Approach
Keep Puppeteer + Chrome `page.pdf()` (tools/build-pdf.mjs). Change what it renders:

1. **Page and viewport**
   - Viewport 1440×810. `emulateMediaType('screen')`, so the screen CSS (layers, tokens, components, layout) applies, not print.css.
   - The page size is 16:9, matching 1440×810 CSS px: `width: '1440px', height: '810px'`, or `@page { size: 1440px 810px; margin: 0 }` with `preferCSSPageSize`. Use `printBackground: true`.
   - Make sure the 1440px layout is what gets laid out: no scaling to an A4 width, and `scale: 1`.
2. **A PDF-mode hook**
   - Add a class (e.g. `html.pdf-slides`) that the build script sets before rendering, plus a small stylesheet `css/pdf.css` linked from index.html with `media="screen"`. Every rule must sit under `html.pdf-slides`, so the normal site is untouched.
   - Alternatively, inject the CSS from build-pdf.mjs via `page.addStyleTag` with a file path. Prefer this if it keeps index.html and the live site unchanged. **Preferred:** inject `tools/pdf-slides.css` at build time, so the deployed site does not ship PDF-only CSS. It must still not be published: confirm that the stage-pages allowlist excludes tools/.
   - In PDF mode:
     - **Header:** hide the fixed site header and the mobile nav. Remove `body` top padding.
     - **Motion:** turn off all animations and transitions, and show the final states. The cover circles and text are fully visible. Do not leave the `html.js` initial opacity:0 states.
     - **Cover:** exactly one 16:9 page (`block-size: 810px`), with the circles as on the web at 1440×810.
     - **Keywords:** 4 pages, one per step.
       - Each page shows the web's switched state for step n: the top line (step 1 heading text, or the project link for steps 2–4), "(n/4)", the line, and the circle word at 0° rotation, inside the sage half-circle. It must look like the desktop dial at that step.
       - Build it with CSS: lay out each `.keyword-step`/block as its own 810px page with the circle, instead of the sticky track. Copy the visual rules; don't use the scroll JS.
       - Hide "SCROLL DOWN" in the PDF, since there is nothing to scroll; mention this.
     - **Skills:** one page.
     - **Career heading and companies:**
       - Each company starts on a new page (`break-before: page`), with the Career heading on the first company's page.
       - Cards keep the web's 3-column grid at 1440, and `break-inside: avoid` on cards.
       - A company with more cards than fit on one 810px page continues on the next page. No card is cut.
       - Pad the top of continuation pages a little, so cards don't touch the page edge. Each page gets vertical padding of about 48–64px.
     - **Contact:** last page, with the panel as on the web.
     - **Footer:** sits on the Contact page if it fits.
     - **Lazy images:** set `loading` to eager before rendering, and wait for all images and fonts.
3. **Images**
   - Keep the current approach: strip `<source>` so JPEG `src` is used (the existing step in build-pdf.mjs). Keep the size under 5MB; report it.
   - If images look soft at 1440, use the larger JPEG candidate from srcset for `src`, within the size budget.
4. **Phone number:** keep the existing injection from the gitignored `private/contact.json` at build time, and its checks (phone text present, a tel link matching it). Never print the number.
5. **Fonts**
   - The PDF must embed TrueType Pretendard, not woff2 (Type3).
   - The existing print path uses a "Pretendard Print" TTF face under `@media print`. With screen media that rule will not apply, so the PDF-mode CSS must switch `font-family` to the TTF faces (declare `@font-face` for the TTF files in `fonts/print/`).
   - Keep the `fonts: TrueType Pretendard only (type3 0 …)` assertion passing.
