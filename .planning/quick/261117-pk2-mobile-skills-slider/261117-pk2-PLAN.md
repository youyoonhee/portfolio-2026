# Quick 261117-pk2: mobile Tech stack slider

## Objective
The user asked on 2026-11-17 that, on mobile, the Tech stack section (`section#skills`, `dl.skills`, 5 card `div`s) become a swipe slider that shows exactly one card per screen. Tablet and desktop (≥ 640px) keep the current 2/3-column grid. The user's explicit request overrides the design-taste "no carousel" preference. No library: native CSS scroll-snap only, plus a few lines of vanilla JS for the indicator.

## Design (fixed)
- **Slider, below 640px:** `dl.skills` becomes the horizontal scroller.
  - Layout: `display: grid; grid-auto-flow: column; grid-auto-columns: 100%; grid-template-columns: none`.
  - Scrolling: `overflow-x: auto; scroll-snap-type: x mandatory; overscroll-behavior-x: contain`.
  - Cards: each card `div` gets `scroll-snap-align: start`, with the same gap as today.
  - Scrollbar: hidden visually (`scrollbar-width: none`, `::-webkit-scrollbar`) because the dots replace it.
  - Exactly one card is visible at 320, 375 and 414. No partial next card. Card height may vary, so align cards to the top.
- **Indicator:** below the slider, a row of 5 small dots (`<div class="skills-dots">` with 5 `<button type="button">`).
  - Labels: each button's `aria-label` is "Markup & Style 보기" and so on, taken from each card's `dt`. The current one has `aria-current="true"`.
  - Size: dots are 8px visually but each button is a 44×44px hit area.
  - Behaviour: clicking a dot calls `scrollTo` on that card. Use `behavior: smooth` only under `prefers-reduced-motion: no-preference`.
  - Sync: `main.js` updates the current dot from the scroll position (scrollend, or a rAF-throttled scroll handler, falling back to IntersectionObserver).
  - Visibility: the dots are created by JS and exist only below 640px. Without JS, the slider still swipes and the dots are absent.
  - Colours: inactive dots use `--color-line-strong`, the current dot uses `--color-accent`. Both are at least 3:1 non-text contrast on white, which check-contrast already covers.
- **Accessibility:**
  - The scroller gets `tabindex="0"`, `role="region"` and `aria-label="Tech stack 목록, 좌우로 넘겨 보기"` only while it is a slider (below 640px). JS sets and removes these on a `matchMedia('(width < 640px)')` change.
  - Arrow keys scroll natively because the region is focusable. Add a visible focus ring with the global style.
  - Card content order and `dl`/`dt`/`dd` semantics stay unchanged.
- **Print:** the PDF keeps the existing grid (print.css already lays out `.skills`). Make sure the slider rules are scoped to `@media screen and (width < 640px)` and that the dots are `display: none` in print. The PDF page count stays at 7.
- **No new motion** beyond native snap scrolling.
